## Why loops are slow

In Lecture 1 the three nested `for` loops cost a couple of microseconds *per pair*, mostly because the Python interpreter has to look up types, allocate small objects and dispatch every operation one at a time. NumPy avoids this overhead by running loops in compiled code, on arrays stored contiguously in memory, with one interpreter call per *array operation*. Writing the algorithm as operations on whole arrays instead of single numbers is called **vectorising**.

Vectorising does not change the algorithm: direct summation still does <M t="N^2" /> pair evaluations. It shrinks the cost of each one by a large constant factor (about <M t="40" />&ndash;<M t="60\times" /> here), and it also changes the price you pay in *memory*. Both effects will matter when you meet trees and meshes.

## Broadcasting

NumPy combines arrays of different shapes by **broadcasting**: compare the shapes from the right; axes of equal length match, and an axis of length <M t="1" /> is stretched to fit the other. A one-dimensional toy example: subtract every position from every other.

```python title="s1_broadcast_toy.py"
import numpy as np

x = np.array([0.0, 1.0, 3.0])        # three particles on a line
dx = x[None, :] - x[:, None]         # shapes (1,3) - (3,1) -> (3,3)
print(dx)                            # dx[i, j] = x[j] - x[i]
# [[ 0.  1.  3.]
#  [-1.  0.  2.]
#  [-3. -2.  0.]]
print(dx.sum(axis=1))                # sum over j for every i: [ 4.  1. -5.]
```

Here `x[None, :]` has shape <M t="(1,3)" /> and `x[:, None]` has shape <M t="(3,1)" />; the difference has shape <M t="(3,3)" /> with entry <M t="[i,j]=x_j-x_i" />. Row <M t="i" /> of this table holds everything particle <M t="i" /> needs; summing along `axis=1` adds over <M t="j" />.

For particles in three dimensions the same idea gives an <M t="(N,N,3)" /> array of separation vectors:

```python title="s2_shapes.py"
import numpy as np

N = 4
pos = np.random.default_rng(0).random((N, 3))
d = pos[None, :, :] - pos[:, None, :]      # (1,N,3) - (N,1,3) -> (N,N,3)
r2 = (d**2).sum(axis=2)                    # sum over x, y, z -> (N,N)
print(d.shape, r2.shape)                   # (4, 4, 3) (4, 4)
print(d[1, 2] - (pos[2] - pos[1]))         # [0. 0. 0.]: d[i, j] = r_j - r_i
```

From here the force is the loop of Lecture 1 in array form: compute the softened squared distance <M t="r^2=|\vect d|^2+\epsilon^2" />, turn it into the weights <M t="m_j/(r^2)^{3/2}" />, multiply the separation vectors by the weights, sum over <M t="j" />, and multiply by <M t="G" />. The only new skill is combining arrays of different shapes. The rule for multiplying an <M t="(N,N)" /> table by an <M t="(N,N,3)" /> table is the same as before: shapes are aligned from the *right*, so add an axis at the *end* of the table; a per-particle array such as `mass` has shape <M t="(N,)" />, and `mass[None, :]` has shape <M t="(1,N)" /> and scales column <M t="j" /> by <M t="m_j" />.

```python title="s5_weights_shapes.py"
import numpy as np

w = np.arange(6.0).reshape(3, 2)           # an (N, M) table of numbers
d = np.ones((3, 2, 3))                     # an (N, M, 3) table of 3-vectors
print((w[:, :, None] * d).shape)           # (3, 2, 3): add an axis at the END of w
print((w[:, :, None] * d).sum(axis=1).shape)  # (3, 3): sum over the middle axis
m = np.array([1.0, 2.0])                   # one number per column (shape (M,))
print((m[None, :] * w).shape)              # (3, 2): scales column j
```

Assembling this is Homework 3.1. There is one trap.

<Callout kind="pitfall">
On the diagonal <M t="i=j" /> the separation is zero, so with <M t="\epsilon=0" /> the weight is <M t="0/0" /> or <M t="1/0" />, giving `inf` or `nan`, and one `nan` in a sum ruins the whole row. Handle the diagonal *explicitly, before the division*: give the diagonal of <M t="r^2" /> a safe value, then remove the self term. (Multiplying a `nan` by zero afterwards does not help: it is still `nan`.) Make sure the self-force is exactly zero. Do not rely on <M t="\epsilon>0" />: your code must work for <M t="\epsilon=0" /> too.
</Callout>

```python title="s3_diagonal_trap.py"
import numpy as np

r2 = np.array([[0.0, 1.0], [1.0, 0.0]])    # squared distances of two particles
with np.errstate(divide="ignore"):
    print(1.0 / r2**1.5)                   # [[inf 1.] [1. inf]]
```

The potential energy of Lecture 1, <M t="U=-\sum_{i<j}Gm_im_j/\sqrt{r_{ij}^2+\epsilon^2}" />, vectorises the same way (the diagonal has the same <M t="1/0" /> trap at <M t="\epsilon=0" />). Summing over the whole <M t="(N,N)" /> table counts every pair twice: either halve the sum or use only the upper triangle (for example with `np.triu_indices`).

## Memory and chunking

The price of vectorising is memory. An <M t="(N,N,3)" /> array of 64-bit floats takes <M t="24N^2" /> bytes, and the expression <M t="\vect d^2" />, the weights times <M t="\vect d" />, and so on each create *another* temporary array of similar size.

| <M t="N" /> | one <M t="(N,N,3)" /> array | typical peak (about <M t="2.7\times" />) |
|---:|---:|---:|
| <M t="10^3" /> | 24 MB | 64 MB |
| <M t="2\times10^3" /> | 96 MB | 256 MB |
| <M t="10^4" /> | 2.4 GB | 6.4 GB |
| <M t="10^5" /> | 240 GB | impossible |

The peak at <M t="N=2000" /> was measured for a straightforward broadcast implementation (Python's `tracemalloc` module reports the peak memory allocated by NumPy); the other rows scale it by <M t="N^2" />. The fix is **chunking**: process the particles <M t="i" /> in blocks of, say, <M t="B=100" />, so that the temporary arrays have shape <M t="(B,N,3)" /> instead of <M t="(N,N,3)" />. The result is identical, the peak memory drops by roughly <M t="N/B" />, and the speed is almost unchanged as long as <M t="B" /> is large enough to keep NumPy busy. For <M t="N=2000" /> and <M t="B=100" /> the peak fell from <M t="256" /> to <M t="14.5" /> MB (a factor <M t="18" />).

<Callout kind="pitfall">
When you process rows <M t="i_0,\dots,i_1-1" />, the diagonal entries of the block are the cells <M t="(i_0+k,\ i_0+k)" />, *not* <M t="(k,k)" />. Forgetting the offset is the most common chunking bug: it passes for the first block and silently gives wrong forces for all others. In code, the block is `pos[i0:i1, None, :]` against `pos[None, :, :]`; the diagonal cells of the block are offset by the block start. Zero the diagonal weights in the block just as in 3.1. Test with a chunk size that does not divide <M t="N" />.
</Callout>

## An equilibrium test object: the Plummer sphere

Simulations need initial conditions. One of the simplest realistic ones is a spherical cluster in *equilibrium*, the **Plummer sphere**. It is also useful as a test: if your force and integrator are right, an equilibrium model should stay put.

<Callout kind="history" title="History">
H. C. Plummer (1911) introduced this density profile to fit the star counts of globular clusters. The same functional form gives the softened force of Lecture 1: the force that a Plummer sphere of scale length <M t="\epsilon" /> exerts on a point mass is <M t="Gm\,r/(r^2+\epsilon^2)^{3/2}" />. In this sense a softened particle acts on other particles as if it were smeared into a tiny Plummer sphere.
</Callout>

### The model

For total mass <M t="M" /> and scale length <M t="a" />,

<M d tag="1" id="eq-l03-plummer" t="\begin{gathered}\rho(r)=\frac{3M}{4\pi a^3}\Big(1+\frac{r^2}{a^2}\Big)^{-5/2},\\[4pt] M(<r)=M\,\frac{r^3}{(r^2+a^2)^{3/2}},\\[4pt] \Phi(r)=-\frac{GM}{\sqrt{r^2+a^2}} .\end{gathered}" />

The density is flat near the centre and falls as <M t="r^{-5}" /> outside. Half of the mass lies inside <M t="r_{1/2}=a/\sqrt{2^{2/3}-1}\approx1.305\,a" />. The model is in equilibrium (with the isotropic distribution function <M t="f(E)\propto(-E)^{7/2}" />, which is why the velocity recipe below has the form it has; you do not need it beyond that) and satisfies the virial theorem <M t="2K+U=0" />, with <M t="K" /> and <M t="U" /> the kinetic and potential energy of Lecture 1; its total energy is <M t="E=-3\pi GM^2/(64a)" />. (In <M t="N" />-body units, <M t="G=M=1" /> and <M t="E=-1/4" />, this means <M t="a=3\pi/16\approx0.59" />; in this lecture we simply take <M t="a=1" />.)

### Sampling positions: inverse transform

Draw a uniform random number <M t="u" /> strictly inside <M t="(0,1)" /> (at <M t="u=1" /> the radius would be infinite) and interpret it as the *mass fraction* <M t="M(<r)/M" />. Solving Eq. (1) for <M t="r" /> gives

<M d tag="2" id="eq-l03-invtransform" t="r=\frac{a}{\sqrt{u^{-2/3}-1}} ." />

This is **inverse-transform sampling**: to draw from a distribution with cumulative function <M t="F" />, draw <M t="u" /> uniformly and return <M t="F^{-1}(u)" />. The direction is uniform on the sphere: take <M t="\cos\theta" /> uniform in <M t="[-1,1]" /> and <M t="\phi" /> uniform in <M t="[0,2\pi)" />, then <M t="(x,y,z)=r\,(\sin\theta\cos\phi,\ \sin\theta\sin\phi,\ \cos\theta)" />. (Choosing <M t="\theta" /> itself uniformly would crowd particles at the poles.)

### Sampling velocities: rejection sampling

For the isotropic model, the speed of a particle at radius <M t="r" /> is a fraction <M t="q" /> of the local escape speed <M t="v_{\rm esc}=\sqrt{2|\Phi(r)|}=\sqrt{2GM}\,(r^2+a^2)^{-1/4}" />, and <M t="q" /> has the distribution

<M d tag="3" id="eq-l03-gq" t="g(q)\propto q^2(1-q^2)^{7/2},\qquad 0\le q\le1 ." />

This cannot be inverted in closed form, so use **rejection sampling**: draw <M t="x" /> uniformly in <M t="[0,1]" /> and <M t="y" /> uniformly in <M t="[0,0.1]" /> (the maximum of <M t="g" /> is below <M t="0.1" />), and accept <M t="q=x" /> if <M t="y<x^2(1-x^2)^{7/2}" />. (The curve <M t="g" /> is unnormalised, which is fine: only its shape matters.) Repeat until you have <M t="N" /> accepted values. The velocity is <M t="q\,v_{\rm esc}" /> times a random direction (as above). Give every particle the mass <M t="M/N" />. Finally, subtract the mass-weighted mean position and velocity so that the cluster's centre of mass is at rest at the origin.

```python title="s4_sampling_toys.py"
import numpy as np

rng = np.random.default_rng(1)
n = 100000

# Inverse-transform sampling: want p(x) = 2x on [0, 1].
# Its cumulative distribution is F(x) = x**2, so x = sqrt(u) for uniform u.
x = np.sqrt(rng.random(n))
print(x.mean())                      # about 2/3

# Rejection sampling: want p(x) proportional to x (1 - x) on [0, 1] (peak 1/4).
x = rng.random(n)
y = 0.25 * rng.random(n)
keep = x[y < x * (1 - x)]            # keep points under the curve
print(keep.mean(), len(keep) / n)    # about 0.5; about 2/3 kept
```

<Callout kind="idea">
Both techniques answer "how do I draw random numbers from a distribution I only know as a formula?". Inverse transform is exact and needs the cumulative function; rejection sampling needs only the density and a bound, but wastes some draws. Cosmological initial conditions (Lecture 7) use Gaussian random fields, drawn with yet another variant of the same ideas.
</Callout>

### How to check a sample

Never trust a sampler without tests. Cheap and strong tests: the total mass and centre of mass; the fraction of particles inside <M t="r=a" /> (analytic <M t="2^{-3/2}=0.354" />); the half-mass radius (<M t="1.305\,a" />); every speed below <M t="v_{\rm esc}" />; and the **virial ratio** <M t="2K/|U|" />, which must be <M t="1" /> for equilibrium. For a sample with <M t="N=4000" /> the virial ratio scatters by about <M t="\pm0.01" /> (one standard deviation), and for <M t="N=500" /> by about <M t="\pm0.03" />; so test against a band of a few standard deviations, not one.

## Does the sphere stay in equilibrium?

Evolve the sample with leapfrog. In Lecture 2 the stepper called your loop force; now the force is a *function you pass in*, with the signature `force(pos, mass, G, eps)` <M t="\to" /> accelerations <M t="(N,3)" />, so the same stepper can use the fast NumPy force (and, in Lecture 6, a mesh force with the same signature). The natural time unit is the dynamical time <M t="\sqrt{a^3/GM}" />, which is <M t="1" /> here; a particle at radius <M t="\sim a" /> crosses the cluster in a few of them. Track the **Lagrangian radii**: the radii (about the centre of mass) enclosing fixed fractions of the total mass, e.g. 10%, 50%, 90%. They are robust, cheap measures of a cluster's structure. For the Plummer model, the radius enclosing a mass fraction <M t="f" /> is <M t="a/\sqrt{f^{-2/3}-1}" />.

There is also a tiny systematic effect: softening makes <M t="|U|" /> slightly smaller than the Newtonian value, raising the ratio by about <M t="0.004" />. Do not look for a 5% systematic effect. Because <M t="N=500" /> is small, real (two-body) relaxation also changes the inner radii a little over ten dynamical times.

### Collisionless or collisional?

Real dark matter is collisionless: particles never scatter individually. A simulation with a finite number of particles approximates this only if the particles do not exchange energy through close encounters over the run time. The **relaxation time** (Binney & Tremaine, Sec. 1.2), the time over which encounters change a particle's velocity by of order itself, is roughly (this is an estimate, not an exact formula)

<M d tag="4" id="eq-l03-trelax" t="t_{\rm relax}\approx\frac{0.1\,N}{\ln N}\,t_{\rm cross}." />

where <M t="t_{\rm cross}\sim\sqrt{R^3/GM}" /> is the time to cross the system (<M t="R" /> a typical radius, for example <M t="a" />). For <M t="N=10^3" /> that is only about 14 crossing times; for <M t="N=10^4" /> about 110; for <M t="N=10^6" /> about <M t="7\times10^3" />. This is why cosmological simulations need very many particles and softening: both keep <M t="t_{\rm relax}" /> much longer than the simulated time.

## Cold collapse

Now the opposite of equilibrium. Take a uniform sphere (radius <M t="R" />, mass <M t="M" />) with *zero* velocities: sample <M t="r=R\,u^{1/3}" /> and isotropic directions (why the cube root? Hint: apply the inverse-transform idea of the previous section to <M t="M(<r)\propto r^3" />). Its energy is <M t="E=-3GM^2/(5R)" /> and <M t="2K/|U|=0" />. Gravity pulls everything inwards, and (for an exactly uniform sphere) all shells reach the centre at the same time, the **free-fall time**

<M d tag="5" id="eq-l03-tff" t="t_{\rm ff}=\frac{\pi}{2}\sqrt{\frac{R^3}{2GM}} ," />

which is <M t="1.11" /> for <M t="G=M=R=1" />. A sampled sphere is only approximately uniform, so its collapse is not exactly simultaneous and the minimum radius comes a little later (at <M t="t\approx 1.1\text{--}1.2" />). What follows is a violent, non-linear process.

Three lessons. (i) The collapse is pinpointed by <M t="t_{\rm ff}" />. (ii) The system does not stay collapsed: it bounces, exchanges energy, and settles into a roughly virialised state with <M t="2K/|U|" /> close to (here slightly above) <M t="1" /> (*violent relaxation*); this is a small model of how halos form. (iii) A fixed time step is wrong for the collapse: the density (and hence the acceleration) rockets up at the bounce, so the energy error spikes. This is exactly the situation for which Lecture 2 introduced a step that shrinks with <M t="|\vect a|" /> (Choosing the time step there); you can try it as an optional extension.

## Summary

- Vectorising removes interpreter overhead (about 40&ndash;60x here) but not the <M t="N^2" /> cost, and costs <M t="\Oh{N^2}" /> memory unless you chunk.
- Broadcasting builds all pair separations as an <M t="(N,N,3)" /> array; the diagonal needs explicit handling.
- Inverse-transform and rejection sampling generate initial conditions from analytic distributions; test every sampler.
- Equilibrium tests: virial ratio and Lagrangian radii. A cold collapse tests the opposite regime and shows why time steps must adapt.
- Enough particles and softening keep the system collisionless over the run.
