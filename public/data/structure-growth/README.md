# Structure formation data

Powers the interactive at [/explore/structure-growth/](https://skoonkor.github.io/explore/structure-growth/).

Cosmological dark-matter-only simulations run with [SWIFT](https://swift.strw.leidenuniv.nl/)
2026.04, from initial conditions generated with [MUSIC](https://www-n.oca.eu/ohahn/MUSIC/)
(Eisenstein–Hu transfer function, 2LPT). These are runs made for this page, not
a published result; the numbers here are not a substitute for a paper.

Generated by [`tools/structure/export_web.py`](https://github.com/SKoonkor/skoonkor.github.io/blob/main/tools/structure/export_web.py).

## The runs

100 Mpc/h box, 128³ = 2,097,152 particles, z = 50 → 0, **one random seed for the
whole grid** — so at early times every universe on the grid is pixel-for-pixel
the same, and everything that differs later is the cosmology and nothing else.

Ω_b scales with Ω_m at fixed baryon fraction f_b = 0.151667. Holding Ω_b fixed
instead would give f_b = 0.30 at Ω_m = 0.15, which is excluded by BBN and the
CMB and puts a baryon feature in the transfer function that has nothing to do
with the effect being shown.

Softening is 1/25 of the mean interparticle separation. The mean separation is
142.25/128 Mpc = 1111 kpc, so the softening is 44.5 kpc comoving.

## Files

| file | size | what |
|---|---|---|
| `structure.json` | ~20 KB | the grid, the shared epoch list, and an analytic growth history per run |
| `pk.json` | ~100 KB | matter power spectra, one row per epoch per run |
| `../../structure-frames/<tag>/frame_NNN.avif` | 24 KB each | 512² greyscale projections |

`z[]` and `k[]` are stored **once**, not per run: every run lands on exactly the
same scale-factor grid and the same k bins, and `export_web.py` asserts it.

## Frames

Each frame is a 15 Mpc/h-deep slab through the box, projected to 512² with an
SPH kernel (64 neighbours — at swiftsimio's default 24 the kernel is the same
size as the 128³ Lagrangian grid and the initial particle lattice prints through
the image as visible squares).

Pixel value is `log₁₀(1 + δ)` mapped linearly onto **the same** black and white
points, `[-0.9, +1.8]`, for every frame and every run. That shared stretch is
what makes the growth real: renormalising per frame would make every epoch look
equally clumpy.

## The power spectra

`P` is in Mpc³ with the shot noise **already subtracted** by SWIFT, and `k` is
in 1/Mpc (h-free, matching the snapshots).

`usableBins` gives, per epoch, how many leading k bins carry a signal above the
shot-noise floor (`P > shotNoise`). That is a floor test, not a true
signal-to-noise ratio: at the first few bins only a handful of modes contribute
and sample variance, not shot noise, dominates the error. Beyond it the true power is below the V/N shot noise and the
subtraction goes negative — 28% of the grid, all above z ≈ 6.5. Those entries
are kept as they are rather than clipped, but **only the first `usableBins[i]`
should be plotted**. The usable range grows from a few bins at z = 45 to all 35 by z ≈ 4, which is simply structure forming.

## Caveats

A 100 Mpc/h box has no power below its fundamental mode, k = 0.063 h/Mpc — which is
**0.044 Mpc⁻¹**, the unit `pk.json` actually uses. (The smallest bin there is 0.056
Mpc⁻¹.) It does not contain the BAO
scale. It holds roughly 29 halos above 10¹⁴ M☉/h, so the page makes no
quantitative claim about cluster abundance. σ₈ measured back out of a single
realisation in this box comes in about 4% low from the missing large-scale modes
alone, which is expected and not an error.
